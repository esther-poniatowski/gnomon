# Current assessment of the Swift–Hohenberg description specification

## Result

The phenomenon is fixed as the capacity to possess stationary localized profiles. Its named structural features remain open. The descriptive question uses `structures_to_match` to require every feature without treating the features as measurements or asking for an explanation.

## Global issues

The requirement registry adds no field for the `description` aim. The Swift–Hohenberg question voluntarily lists every requested feature under `structures_to_match`, but the validator would also accept a descriptive question with no coverage targets. The aim should require a feature-coverage list, or the accuracy block should make that list mandatory when `standard: structural-only`.

The requested targets identify what a description must cover, but they do not state the resolution at which branch variation over `(r, b)` must be reported. A per-target coverage domain or grain would make partial catalogues assessable.

The local `powerset` constructor leaves its result type open. The records can state sets of profiles, topology labels and stability intervals, but the operator checker cannot verify the resulting set type.

## Deliberately open science

The requested branch characterization is the descriptive product. Its feature values therefore remain open in the phenomenon record. No candidate catalogue or assessment is supplied.
