# Handoff — framework corrections

The designer has ratified a reorientation: the inquiry records become a small modeling language rather than forms holding prose. Every declared quantity carries a symbol, and every formula is an expression over declared symbols. Implementation of that reorientation is under way; the candidates it does not absorb remain unreviewed.

## Reorientation

The five cases established that referencing is already load-bearing and already unreliable. Within a record, `defined_over`, `applies_to` and `shares` resolve by exact equality of a prose name; across records, `question.subject.domain` reaches a target parameter the same way, while `target_system` and `phenomenon` use identifiers. The prose names carry a symbol, a gloss, a signature and sometimes a definition at once, so a formula can name a quantity that no entry declares.

Two ratified stages replace that arrangement. ^stages

| Stage | Content | Consequence for the records |
| --- | --- | --- |
| **A — symbols** | Every declared quantity carries a `symbol` unique within its record. `name` holds a gloss only. Every reference and every formula names symbols. | One quantity per entry. References resolve mechanically. |
| **B — expressions** | A formula is an expression over declared symbols, with index variables bound by an aggregator. The free indices of the expression are the signature of the quantity it defines. | Aggregation over several indices is expressible. Grain is derived, not restated. |

[The syntax, the binders and the resolution rule](../docs/epistemology/symbols-and-expressions.md) own this contract. A stage is not complete while any dependent record still resolves a reference by prose.

Three vocabularies meet in a filled inquiry, and each has one author and one reach. ^three-vocabularies

| Vocabulary | Author | Reach | Where it lives |
| --- | --- | --- | --- |
| Fields and their option lists | Designer | Every problem | The method notes and the templates, kept aligned by the structural checks. |
| Symbols of one problem | Author of that problem | Its own records | The records themselves, collected into one generated table per problem. |
| Operators | Mixed | Canonical part everywhere, the rest in one problem | [The canonical set](../docs/epistemology/symbols-and-expressions.md#^operator-groups) in the registry; the remainder in the `operators.yml` of the problem, read by every record of that problem. |

## Verification contract

Each stage uses the narrowest checks that exercise its changes. A shared template change still requires every dependent fixture and downstream template to be checked.

- **Documentation and template alignment:** every method-table row resolves to one template key in the same order, and no template key lacks documentation.
- **Symbol resolution:** every symbol is unique within its record; every reference and every identifier occurring in a formula resolves to a declared symbol; every rule has a planted negative case that fails for the intended reason.
- **YAML integrity:** every template and fixture parses, retains its `id` and `type`, and contains no uppercase placeholder.
- **Reference integrity:** each cross-record identifier and Markdown link resolves to one existing target.
- **Downstream consistency:** changes to task requirements also update every answer or assessment field that consumes them.

The documented `gnomon` conda environment is absent. Python must not run in the base environment; the current work used `dev` for read-only checks. Obtain approval before creating the project environment or installing anything.

| 2026-09-23 | Collect the operators of a problem in one file, read against the whole problem. | An operator was typed over sets declared in the target and used in the phenomenon, so no single record both owned it and could type it. |

The admissibility of an aggregate is already a satisfaction test, and the commitment belongs to [the declaration that introduces the aggregate](../docs/epistemology/target-system.md#^aggregate-admissibility). |
| 2026-09-23 | Do not read the absence of a case from the seven fixtures as the absence of a requirement. | The fixtures request no causal relation, yet causal inquiries are ordinary. A field is justified by the design, not by how often the current corpus exercises it. |
| 2026-09-23 | Name the record kinds the checkers read, separately from the blocks that declare symbols. | One constant had served both purposes, so adding a kind that declares nothing silently excluded it from every check. |
| 2026-09-23 | Connect a dead declaration rather than deleting it, where the record can say what it was for. | Four microbial coefficients now type the interaction specification, a delayed-generalization law now draws the parameters from the declared initialization distribution, and an active-matter domain is the region its size and boundary geometry fix. Deleting them would have discarded the typed content and hidden the missing law. |
| 2026-09-23 | Let a requirement path traverse a list, rather than reading a block of tokens. | A field whose entries carry a reason is a list of mappings, and an aim requiring a value of every entry needs a path that reaches inside them. |
| 2026-09-23 | Write a modulating condition as a relation over declared symbols rather than as a direction in words. | `increasing` and `decreasing` were already canonical, since a manifestation may take the form of a dependence, so the direction of a modulation needed no vocabulary of its own. |
| 2026-09-23 | Admit no `open` in an external constraint, and mark a genuine unknown with `maturity` instead. | The value carried two readings that a reader cannot tell apart, and one of them silently hides the quantities a constraint would have named. |
| 2026-09-23 | Require every carrier of an interaction to be indexed by both its endpoints. | That is what makes the record readable as a graph: a quantity indexed by the source alone states a property of the source, not an influence on anything. |
| 2026-09-23 | Generate the interaction graph at the level of kinds rather than of members. | Which ordered pairs are joined is fixed by a parameter of a member model, which a target record does not value, so the record states where to read the edges from instead of listing them. |
| 2026-09-23 | Express a variant as a partition of one symbol table, not as a nested schema. | One flat table per record is what the uniqueness rule and every cross-record reference assume, so a nested schema would introduce scopes for one attribute. |
| 2026-09-23 | Keep a quantity every member has at the root, and let the laws differ. | Renaming the microbial growth law per variant broke the phenomenon that takes its Jacobian: every member has a growth law, and what differs is what that law takes, which is what a law states. |
| 2026-09-23 | State an interaction on the law that asserts it, not in a block of its own. | The block restated the law wherever one existed, and where none existed the record could write one: a dependence of a growth law on a coefficient is falsifiable and expressible with the canonical relations. |
| 2026-09-23 | Merge the internal and exogenous variables, and keep the parameters apart. | No key belonged to one of the three blocks alone, so the first two encoded one distinction. The parameter boundary survives because it carries a rule: a parameter may not be indexed by the course. |
| 2026-09-23 | Return the overparameterization restriction to the question, reversing the move of 2026-09-22. | That move was forced by the domain holding one parameter to a set, which no joint proposition fits. The domain now carries a joint restriction, so the constraint sits with the inquiry that imposes it and another question may be put below the same line. |
| 2026-09-23 | Read the endpoints of an influence from the order of its pairs. | Naming them separately restated `applies_to` on one side and the pair order on the other, and for an influence between two of one kind the pair of names carried nothing at all. |
| 2026-09-23 | Rebuild a vocabulary from what the records assert, not from what the first cases needed. | `constraint` had become the bucket for three fifths of the laws, which is what `distribution-statistics` had been for aggregation: a value that separates nothing is a value that hides what it holds. |
| 2026-09-23 | Admit an influence of more than two places. | A binary product presupposed that every influence has one source, which is the fixed arity the phenomenon records were corrected for: a higher-order term carries an effect that neither of its two sources carries alone. |
| 2026-09-23 | Merge a block boundary that only restates what an entry names. | A restriction on a parameter and one on a variable differ in the quantity they name, which the target record already classifies; keeping them apart left the one real rule — that only a variable can be clamped or held stationary — implicit in the split and unchecked. |
| 2026-09-23 | Read which members carry a symbol from the target, in the phenomenon as in the laws. | A phenomenon declares no variant of its own, so the rule that an unmarked claim must be readable by every member it ranges over needs the fact one record upstream. |
| 2026-09-23 | Let a maturity marker license an incompleteness a check would otherwise report. | The marker had no consumer, so a record could admit a gap and nothing would read the admission; a check that consults it distinguishes an omission from a decision. |
| 2026-09-23 | Give an operator type variables before elevating any. | An operator typed at its one call site carries that site into every record that inherits it: an elevated adjoint would have brought one problem's state space with it. |
| 2026-09-23 | Retire `pow` rather than adding a vector constructor beside it. | Every use of `pow` in the corpus was a vector, so keeping both would have left two spellings for one shape. |
| 2026-09-23 | Name the derivative `diff` rather than `d`. | Operators and quantities share one namespace, and `d` is a declared dimension in two problems, so a canonical `d` would leave `d(u, t)` ambiguous to a reader and to the parser the syntax decision anticipates. |
| 2026-09-23 | Name a field for what it decides, and never twice in one record. | `level` suggested a position in a hierarchy while bounding a vocabulary, and a reader of the registry could not tell which of the two fields its key named. |
| 2026-09-24 | Let an explanans appeal to an external system, and not to a quantity that system owns. | An owned quantity is already reachable as a term under its own symbol, so admitting both would write one appeal two ways. |
| 2026-09-24 | Refine a constraint by the vocabulary a law already uses, not by a new one. | The three constraints written fall inside the roles rebuilt from the twenty-nine laws, so a second vocabulary would have named the same distinctions twice. |
| 2026-09-24 | Give a law of the target the warrant its answer-layer counterpart already carried. | Every law of a target is admitted, and they are not admitted equally. A law derived from other laws stands or falls with them; one posited, fitted or measured stands on a choice, a fit or an instrument, and is the first thing new evidence revises. Everything resting on it inherits that exposure, up to the answer, so which laws a result depends on is only readable once each law says why it is admitted. Of the thirty laws written, twenty-six are posited by the model class, three are derived and one is measured. |
| 2026-09-24 | Declare the answer's model with the target's blocks rather than a vocabulary of its own. | A candidate proposes a system standing in for the target, so a parallel vocabulary had to draw its own distinctions, and the ones it drew restated what the value sets carried. |

| 2026-09-24 | Name the block `organization` and its key `relates`, retiring `influence`. | The word named the causal reading of one relation, where the block holds relations that need not be causal: adjacency and sameness are organizational and neither influences anything. |

The kinds say what the factor is a property of, and a property of a family bears on every element of it. |

## Synchronization debt

- `realizations` and `among` are expressible, checked and unexercised. The first waits on an answer record; the second waits on a case whose activity order no index already fixes.
- `preferred` is unexercised: all ten virtues the corpus fills are constitutive. The value is not idle, since it is what appraisal ranks on and what the comparison record reads, but no filled inquiry exercises the tier. A question weighing economy or tractability between two adequate answers would.
- The rule that a constitutive virtue is settled by the product test and a preferred one by appraisal, each exactly once, is stated in the notes and checked nowhere: it needs an assessment record, and none exists. It belongs with the answer-layer trial.

- The signature of a derived observable is declared, not computed. Until a parser derives it from the definition, a record can declare a signature that its definition contradicts. The resolution test checks references, not arity.
- The canonical operator set is closed by no grammar. It holds the binders that realize the signature rule, the relations that realize the manifestation forms, and one operator of change; a problem needing more declares them in its own records.
- The package is not installed in any environment, so the test suite reaches it through `pythonpath` and the command through `PYTHONPATH=src`. Running `gnomon vocabulary` as an installed script requires an authorized project environment.
- The Markdown view of a vocabulary is built; the view of a filled inquiry record is not, and neither typesets an expression as LaTeX. The records carry the syntax already; the renderer needs a mapping from each operator to its notation, and the operator registry and the `operators.yml` of the problem already hold it.
- Of six external-system constraints, three are written as expressions and three are empty, each empty one saying beside it why nothing is imposed. The coverage and uncertainty of the measurement system bear on the detection criterion rather than on the target, so they are declared nowhere; a detection test that used them would be the place.
- `status` carries a different vocabulary in each record kind. Unlike `kind`, it names one concept — the lifecycle of the record — whose states depend on what the record holds, so the repetition is admitted rather than a generic slot.
- Only the rows reading `always` are checked. The remaining conditions in the same column are semantic, such as an index set required when neither a constituent kind nor a constituent parameter supplies the set.
- A tolerance separates the metric from the bound, so an inquiry that knows how to compare without knowing how close says so. One case fixes a metric, one fixes neither, and a qualitative accuracy carries no tolerance at all.
- A renderer is wanted that composes the question statement from the fields, beside the LaTeX rendering of a filled record. [The syntax decision](../docs/adr/expression-syntax.md) fixes the surface it renders from.
- All six detection tests read `expression: open`, since the pattern each would test is what its inquiry seeks. Their glosses carry what the test checks until the diagnostic exists.
- The key order within an entry is stated in [the representation contract](../src/gnomon/data/templates/_index.md) and enforced by no check. A record whose keys run in another order passes every test.
- The active-matter lattice realization is named and its schema is not written. The check now reports such a variant unless the record marks it open, and this record does, so the gap is declared rather than closed: no lattice member can be generated, and the `continuum` marks on the target and the phenomenon carry information only because that second variant is named.
- The optimizer update of the delayed-generalization record states how the parameters change and not how its auxiliary state does. `d_t(theta, z)` passed two quantities to a derivative, which no reading admits; it is now `diff(theta, step)`, and the law for `z` is unwritten.
- `grad`, `div` and `lap` are typed with a free variable for the dimension, which the type language cannot tie to the domain they run over. The types are honest about the shape and silent about the dimension.
- The arity of an influence is stated and only partly checked: a carrier must be indexed by every place, so naming fewer places than the carrier has leaves every check green. Naming a place no carrier covers is reported.
- The direction of an influence is stated and cannot be checked: reversing the pairs of an edge leaves every check green, since the carrier is indexed by both endpoints either way. This is the class of the declared signature, and a parser would not close it.
- `applies_to` is verified for the six interaction laws alone. The other twenty-three are declared against the new definition and unchecked, because a derivation takes the index of a quantity an operator consumes and misses one applied at a literal index.
- The command is `python -m gnomon`, never `python -m gnomon.cli`: the latter has no `__main__` guard, so it imports the module and exits 0 without doing anything. A regeneration invoked that way reports success and writes nothing.
- The appeal of an explanans is checked and unexercised: no answer record exists, so only a synthetic one runs the check.
- No answer record exists, so the rewritten answer template is unexercised: `separates`, `bears_on`, `through`, `produces` and the model blocks are checked by no case, and neither is the assessment that reads them.
- A detection test carries a name and no symbol, since no field references a test. A symbol becomes warranted as soon as an assessment reports a verdict per test.
- The rule that a gloss must not reformulate its name is checked by hand. The check is a word-overlap heuristic, so it reports entries a reader must triage, which is why it is not in the suite.
- A gloss is authored prose beside a formula, and nothing holds the two together. A gloss that contradicts its expression passes every check; only the style keys and a reader see it.
- The unused-quantity check is lexical, as the operator check is, so a symbol named only inside a gloss counts as reached. A structural count would read the expression and reference fields alone.
- A domain limit is one string pairing a quantity with a value, `Re -> infinity`. Both ends resolve, and the arrow between them is punctuation no operator defines, so nothing checks that the left side is a declared quantity of the target.
- The corpus fills three precipitating conditions and two modulating ones, and no inhibiting condition, nonstandard circumstance or byproduct. Each block left empty for a case-specific reason says so in a comment beside it. The three kinds with no instance need quantities no case declares: a dissipation rate for the turbulent anomaly, an intervention scale for a nonstandard preparation. This is a statement about the fixtures, not about the schema, which now expresses all five.
- Nineteen value sets read `open` because the case fixes no set. Their identifying content sits in the gloss, the place a name in words belongs. A set that is genuinely constrained and not yet expressible has no other home.
- The note option cells remain unchecked against the registry, because a note states a gloss where a template states a token. Carrying both in each cell would close the last leg.
- The schema index names registry schemas that are not present in its directory. Inquiry-schema work must update the index without claiming those unrelated schemas were restored.
- [The assessment record](../src/gnomon/data/templates/_index.md) carries no symbol and no expression. The answer record does, but no instance of either exists, so the answer layer has never been exercised against the language.
