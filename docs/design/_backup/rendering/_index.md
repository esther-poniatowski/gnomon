# Rendering proposals

Each proposal covers one stage of the path from a specification to a finished note.

| Proposal | Content |
| --- | --- |
| [Formal contracts](formal-contracts.md) | The compact specification each note is generated from, treated as the valid unit of work. |
| [Note types](note-types.md) | The two workspace files each note type pairs, and the structural constraints binding the type. |
| [Mathematical pedagogy](math-pedagogy.md) | The argument and structure requirements a mathematical note must meet. |
| [Post-draft audits](post-draft-audits.md) | Verification performed once a draft exists, kept separate from the rules and specifications it checks. |
| [Rendering and views proposal](rendering-and-views.md) | Which source a digest note should be generated from, so that the exposition stays coherent. |
