# Operation schemas

> [!INFO] Tier and source
> **Tier 3 (per aspect).** Instantiates the architectural commitments at [operation-schema primitiveness](vendor/gnomon/docs/design/2-architecture/operations-and-modes#^t2-operation-primitiveness) (open) and [operation-schema placement](vendor/gnomon/docs/design/2-architecture/operations-and-modes#^t2-operation-schema-placement), resolved as operation schemas living in the meta-schema. The architecture commits *that* the operational core is closed, *that* operation schemas are versioned and validated like schema elements, and *that* applied operations reference them. This file fixes the candidate constructors if schemas are generated by a calculus, and the contents required under each reading of primitiveness.

---

## Criteria

### Constructor admissibility specification ^t3-constructor-admissibility

Each constructor that generates operation schemas (or, in alternatives without a calculus, each primitive operation schema) must declare a typed signature, admissibility conditions, transformation semantics, success condition, and license kind. This five-part admissibility specification is the Tier-3 form of what makes the operational core closed, the architectural response to [no infinite regress](../1-framework/expressive-depth#^t1-no-infinite-regress).

## Decisions

### Schema-calculus constructors ^t3-schema-calculus-constructors

> [!QUESTION] Which primitive constructors generate the library of operation schemas? (contingent on [operation-schema primitiveness](vendor/gnomon/docs/design/2-architecture/operations-and-modes#^t2-operation-primitiveness) resolving as schema calculus)

If a calculus generates schemas, the meta-schema declares operation **constructors** rather than enumerating operation schemas. Initial constructor proposals:

- **Sequential composition** — `compose(s1, s2, ...)`: apply schemas in order, threading outputs to inputs.
- **Parallel decomposition** — `parallel(s1, ..., sn)`: apply schemas independently on disjoint sub-targets, gather outputs.
- **Conditional branching** — `branch(condition, s_true, s_false)`: select a schema by a predicate over inputs.
- **Iterative refinement** — `iterate(s, until)`: apply a schema repeatedly until a termination predicate holds.

Constructors compose: a schema built by `compose(branch(...), iterate(...))` is itself an operation schema in the derived library. The proof that constructor chains terminate, required by [no infinite regress](../1-framework/expressive-depth#^t1-no-infinite-regress), follows from the admissibility conditions for the constructors (per [t3-constructor-admissibility](#^t3-constructor-admissibility)).

### Contents under each primitiveness alternative ^t3-contents-per-o5-alternative

> [!QUESTION] What does the library of operation schemas carry under each reading of primitiveness? ([operation-schema primitiveness](vendor/gnomon/docs/design/2-architecture/operations-and-modes#^t2-operation-primitiveness))

The meta-schema placement is the same under all alternatives; only the contents change.

- **Definitional fiat** — the meta-schema enumerates a closed list of primitive operation schemas; the list is asserted, not derived. Contents: a flat list to be drafted by the schema work, drawing on the AC/A2/AG inference tables.
- **Proof that schemas terminate** — the meta-schema enumerates a closed list, with a separate proof that each schema reduces to a fixed computational basis or fits an explicit stratification. Contents: same list as definitional fiat plus the proof by reduction or stratification.
- **Schema calculus** — constructors as proposed in the previous decision; schemas are derived terms.
- **Open library** — ruled out as a pole; no fixed contents.
