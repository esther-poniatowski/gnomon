# Kind, class and population

> [!QUESTION] Goal: over which collection does a law, a model or a claim generalize, and what must that collection satisfy?

Laws, models and claims generalize over a collection of systems. The three terms name that collection under three requirements:

- a **class** is any collection fixed by membership;
- a **kind** is a class whose members share properties that support projection;
- a **population** is a class of units over which a statistical quantity is defined.

## Senses

| Term | Community | Definition | Source |
| --- | --- | --- | --- |
| Class | set theory, logic | a collection fixed by a membership condition, with no further requirement | — |
| Natural kind | philosophy of science | a class whose members share properties that support inductive projection; on one account, a cluster of co-occurring properties maintained by causal mechanisms (a homeostatic property cluster) | [goodman1955]; [boyd1991] |
| Population | statistics, causal inference | the set of units over which a target quantity of a study is defined | [lundberg2021] |
| Intended applications | structuralist view of theories | the set $\mathsf{I}$ of systems to which a theory is meant to apply | [balzer1987] |

## Distinctions

- **A kind is a class that supports projection.** Every collection is a class, whereas only some classes support generalizations from observed members to unobserved members. The class of things that are "grue" is a class and not a kind, since generalizations over it are not projectible [goodman1955].
- **A population differs from a kind by the quantity defined over the population.** A population is chosen so that a summary, such as a mean effect, is defined over its units. A population need not be a kind: the patients enrolled in a trial form a population without sharing a mechanism.

## Consequences for a record

- **The reference class of a target specification names the collection over which the record generalizes.** The [reference class](../../target-system.md) is generated by the other specifications of the target. The [scope over instances](../../phenomenon.md) of a phenomenon states how a claim ranges over the members of that class.
- **A reference class is a class, and its projectibility is a claim to be tested.** A record does not presuppose that its reference class is a kind. The `status` of the field `reference_class.projectibility` states whether the projection of claims from observed to unobserved members is `assumed`, `tested` or `not-claimed`. Its `evidence` gives the test or the argument that supports the projection.
- **A reference class selected on an outcome is a population and may not be a kind.** The [selection on outcome](../../target-system.md#^selection-on-outcome) of a target specification creates associations absent from the full class. Therefore, a claim about the selected members can transfer to the full class only after a check for selection bias.
