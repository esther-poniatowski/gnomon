# Specifying the target system

> [!QUESTION] Goal: what must be fixed to specify the system that an inquiry is about?

The target system is the first component of the [subject of inquiry](subject-of-inquiry.md).

> [!IMPORTANT]
> A target system is a part of the world that the modeller carves out by partitioning and abstraction. Specifying it is a modelling step in its own right [elliottgraves2020].

- **The specifications are admitted as given.** The laws and properties recorded about the system are those admitted *a priori* as relevant to characterize it. The inquiry may still seek new ones. Formal and empirical targets differ only in the closure of those laws. For a formal target, the laws define the system, so a new law must be derivable from them, for instance an effective equation obtained in a mean-field limit. For an empirical target, a new law may be independent of the ones admitted, for instance a newly discovered plasticity mechanism.  *Example*: the Edwards–Anderson spin glass consists of $N$ Ising spins $s_i\in\{-1,+1\}$ on the sites of a lattice, interacting through random couplings $J_{ij}$ between neighbouring sites, with energy $H=-\sum_{\langle ij\rangle}J_{ij}s_is_j$. The state space is $\{-1,+1\}^N$; the site positions and the couplings are parameters, fixed while the spins evolve [edwards1975]. ^constituents
	
- **For the target type, the option "No external target" covers questions about a model class itself**, such as its own [consequences, regimes, limits, structural properties](epistemic-aim.md).
	
- **The reference class is generated by the other specifications.** Its members are the systems that satisfy the constituents, the variables and the laws, with parameters in their admitted value sets as restricted by $D$. For a particular system, the class reduces to that system. The members of the reference class are the instances indexed by $k$ in the phenomenon.

> [!IMPORTANT] No redundancy
> The reference class records only a name and, when needed, selection criteria. It does not restate any of the other specifications. Together they form a schema, and each member of the class is one instance of that schema, with its own parameter values, as a theory specifies a family of models [winther2020]. 

- **Selection criteria are needed whenever membership depends on a property that the other specifications do not fix**, for a formal class as for an empirical one. *Examples*: species or brain area for recorded animals, as eligibility criteria define the population of a clinical trial [ich2019]; convergence of training for trained networks. 

- **A criterion on an outcome of the dynamics can create associations that the full class does not show.** *Example*: across the full class, the learning rate and the initialization scale are set independently, but training converges only when their product stays below a threshold. Among the converged networks, a large learning rate then co-occurs with a small initialization scale. This association comes from the selection alone, since convergence is a common effect of both factors [hernan2004]. Therefore, each selection criterion is marked as fixed *a priori* or dependent on an outcome. A claim about members selected on an outcome does not transfer to the full class without a check for this bias.

- **State variables fix how the phenomena can be expressed.** The explanandum variable of a phenomenon is a *function of the system's state variables* (an "observable"). A variable defined over one constituent, or over a pair of them, corresponds to the [components and relations of a mechanism](mechanism.md).

- **Each entry of a signature resolves to a constituent kind or to an index set, and the two read differently.** An entry resolving to a constituent kind names what bears the quantity, so a system with several kinds of unit fixes which one bears the quantity. An entry resolving to an index set names what the quantity runs along. A signature entry that resolves to neither is a defect, not a new index.

- **A parameter or a variable names the signature it takes**, one entry per place, each entry a constituent kind or an index set: a quantity carried by a single unit names one kind of constituent, a quantity carried by a pair names two, and a quantity of the system as a whole names none. The places are generic, so a connectivity weight defined over two neurons holds for any pair of them. A quantity whose single value holds for every tuple is marked as shared. An aggregate of constituent states is stated with its defining map, "[variable] := [function of constituent variables]". ^places
	
- **An aggregate and a quantity of the whole system differ by derivability.** An aggregate is a function of constituent states, so aggregates are functions on the state space, not additional coordinates. *Examples*: the center of mass is a mass-weighted mean of positions, the temperature of a gas a mean kinetic energy, a population rate a mean over neurons. In contrast, a quantity of the whole system cannot be derived from constituent states. *Example*: the volume of a container. ^aggregate-variables
	
- **An aggregate is a legitimate variable only if interventions on it have unambiguous effects.** Total cholesterol is ambiguous: raising it through LDL or through HDL has opposite effects on heart disease [spirtes2004]; a mean rate over excitatory and inhibitory neurons is ambiguous for the same reason. A model written over aggregates is consistent with the model over the constituents only for aggregations under which interventions on the two correspond [rubenstein2017]. The declaration is where that commitment is made, and [the level test](satisfaction-conditions.md) is where a candidate answer is held to it. ^aggregate-admissibility

- **An aggregation map is carried by its variable, not by a law.** The expression of a quantity merely *introduces* that quantity, so it cannot be false of the system, whereas the expression of a law asserts something that can be. *Example*: the map "population rate := mean of the constituent rates". In contrast, a bridge law *identifies a separately measured quantity with an aggregate*, so it is a factual hypothesis. *Example*: the temperature read by a thermometer equals the mean kinetic energy of the molecules, up to a constant. In reduction theory, the status of such bridge laws is either stipulation or empirical hypothesis [nagel1961]. A bridge law that states an empirical hypothesis belongs to the laws, under the measurement function.

- **Internal variables are the state variables of the system $S$**: their values are determined within $S$, as the values of endogenous variables are determined by variables inside a causal model [pearl2009]. The determining law need not be known: an internal variable may be only measured, and its law may be admitted, sought by the inquiry, or left open. 

- **An external system is fixed by its symbol, the variables it shares, the constraints it imposes on them, and the quantities that specify it.** A heat bath is fixed by its temperature, a generator of inputs by its latent dimension, a decoder by its weights. Each such quantity is declared among the parameters or the exogenous variables of the record and names its owner, so one symbol table serves the whole record and [a question narrows that quantity](domain.md) by the path that narrows a parameter of $S$. A law of an external system that touches no shared variable cannot reach the target, so the specification omits that law. ^external-parameters

- **A variant that no declaration carries names a member the record cannot generate.** The other members stay describable and that one has no schema at all, so the disjunction the class announces holds on one side only. A record may admit the gap by marking the variant open in its [maturity](subject-of-inquiry.md), which is what a maturity marker is for; left unmarked it is reported. The count is of the entries carrying the variant, in every block the record declares in, not of the occurrences of its name, since that name recurs in its own prose and in the marker admitting it. ^unborne-variant

- **A selection criterion conditions membership on an outcome; a restriction on prior values belongs to the question.** One target system serves several phenomena and several questions, so a restriction written here binds every one of them. That is right when the class is a *selected* population, because selecting on an outcome of the dynamics changes what can be inferred from the class and every inquiry must see it [lundberg2021]. It is wrong when one inquiry merely asks its question of some members and another would ask it of the rest: that is a [restriction of the domain](domain.md), which the question imposes and which a joint restriction carries when no single quantity does. ^selection-on-outcome

- **A variant differs in what a member declares; a domain restriction differs in what a member's quantities are worth.** Members of one class may share every declaration and differ only in the values their parameters take, and that difference is a [restriction of the domain](domain.md). Members may instead differ in which quantities and which laws they carry at all, and no restriction of values reaches that: a consumer model with explicit resource pools and one with direct interaction coefficients have different state spaces. The declarations stay in one table, because the resolver and every cross-record reference assume one symbol table per record; a variant is a partition of that table, marked on each entry that only some members carry. An entry left unmarked asserts something of every member, so it may not name a symbol that only some of them have: a law reaches the class through its expression, a relation of the organization through the parts it runs between and the laws realizing it, an external system through what it shares. A mark itself names a declared variant, since one naming none would exempt its entry from a rule while belonging to no member. ^variants

- **A law is admitted, and its warrant says on what.** Every law here is admitted a priori, and they are not admitted equally: one derived from others stands or falls with them, while one posited, fitted or measured stands on a choice, a fit or an instrument, and is what new evidence revises first. The warrant is therefore a property of the law and not of the analysis that uses it, and it propagates: a result resting on a measured law inherits that law's exposure, and so does the answer resting on the result. The [candidate answer](answer-form.md) states the warrant of its own laws in the same vocabulary, so a chain of dependence can be read from end to end. ^law-warrant

- **A relation between two parts is internal, and is not an external interface.** The external systems fix the boundary of $S$, so a relation whose ends are both inside $S$ has no place there. It is stated in the organization, which names the ordered tuples the relation runs along and the laws that state it. Those laws supply what carries it, being the quantities indexed by every place, so nothing is written twice; and the reach is the last component of the tuples, so the direction is the order. A tuple of three or more states a joint relation, which a pair of ends could not: two populations may change the growth of a third together without either changing it alone. ^organization

- **A relation whose ends are laws names them, and orders rather than carries.** The organization of a mechanism covers the arrangement of its activities as well as of its parts [craver2007], so a relation may run between two laws: one runs only after another has completed, or one holds only while another does. Such a relation names the laws in order, the reach last, and no expression carries it, because there is no quantity indexed by a law. It is worth stating only where the law expressions do not already fix the order. Where they share an index that does — a distribution written at step zero beside an evolution written over the steps after it — the relation would restate what the expressions carry, which is why no record of the corpus states one. ^law-ends

- **A constraint of an external system is a claim, and carries what a claim carries.** It states something that can be false of the system and its environment together, so it takes the name, the places it ranges over, the role and the reading that a law of the target takes, under the same closed list of roles. It stays beside the system imposing it rather than among the laws, because the boundary is what that block is for, and because a law of the target is about the target alone. ^external-constraint-shape

- **An external system belongs to a class, as the target does.** The target is fixed by a reference class its specifications generate, and an external system was fixed by a name in words and by what it imposes at the boundary. The class states which systems it may be, so an answer appealing to it appeals to a kind rather than to one description, and two inquiries may appeal to the same kind. What the class implies at the boundary stays in the constraints: the class says what the system is, and the constraints say what follows for the variables it shares. ^external-class

- **External systems enter the specification only through the variables they share with the target system $S$.** An open system interacts with its environment through variables shared at its boundary [willems2007]. The external systems are therefore specified by the properties that constrain those shared variables. These properties pass the [inclusion test](subject-of-inquiry.md#^inclusion-test): an answer may explain the phenomenon by the structure of the inputs, for instance by the latent variables that generate them [goldt2020], or by the class of external system that reads the outputs, for instance a linear decoder. A restriction of their parameter ranges belongs to $D$, as for the parameters of $S$.

- **The boundary is the set of shared variables, and no direction is declared beside them.** The behavioral approach treats every interconnection as a set of shared variables, without a prior partition into inputs and outputs [willems2007]. The partition stays recoverable where it applies: a shared exogenous variable is set outside the system, a shared state variable is determined within it, and a shared state variable that an external system also constrains closes a loop. A declared direction would state a second time what the declaring block already fixes.
	
- **The partition of variables is only provisional.** The constituents, the state variables and the variables shared with an external system record the partition that the researcher *stipulates*, for example an isolated slice or a closed loop with a task environment. In some contexts, the relevant partition is itself partly a *result of the inquiry*. *Example*: in [constitutive explanation](requested-relation.md), a part belongs to the mechanism only if its activity and the system's behavior can each be changed by intervening on the other ("mutual manipulability") [craver2007]. The inquiry may then move a variable across the boundary, for instance by enlarging $S$ to include the task environment.
