# Specifying the target system

> [!QUESTION] Goal: what must be fixed to specify the system that an inquiry is about?

The target system is the first component of the [subject of inquiry](subject-of-inquiry.md). The target-system record is a *target specification*: it delimits the target, the system or the class of possible systems that an inquiry is about. The [vocabulary of things and constructs](../definitions/systems/things-and-constructs.md) separates the target from its specification. The record fixes the referent of the target and declares its quantities. The laws admitted about those quantities are claims, so they are stated in separate [background records](background.md).

> [!IMPORTANT]
> A target system is delimited within the world by the modeller, through partitioning and abstraction. The target system therefore already results from a modelling step [elliottgraves2020].

- **A record at commitment `identified` fixes its referent before any quantity is declared.** The identification names the system or the class by a definite description, with pointers to the data, the results or the publications where it appears. At this commitment, a question can refer to the target, and an inquiry can start, before the declarations exist. The record reaches `specified` once its variables are declared and every symbol of its expressions resolves. The two levels and the checks that decide them are defined with the [levels of commitment](../inquiry/question.md#^commitment-levels). ^target-commitment

- **The option "No external target" of the target type covers questions about a model class itself**: its consequences, regimes, limits and structural properties, under the [aim of knowledge of models](../epistemic-task/epistemic-aim.md).

- **The reference class is generated by the other specifications.** Its members carry the declared constituents and variables, and their parameters lie in the admitted value sets as restricted by the domain $D$. When a question admits a [background record](background.md), the class is restricted further, to the members that obey the admitted laws. When the target is a particular system, the class has a single member. In the phenomenon, the members of the reference class are the instances indexed by $k$.

> [!IMPORTANT] No redundancy
> The reference class records only a name and, when needed, selection criteria, and restates none of the other specifications. No restatement is needed, because the other specifications together already form a schema. Each member of the class instantiates that schema with its own parameter values, as a theory specifies a family of models [winther2020].

- **Projectibility is a claim about the class, and it can be tested.** A claim established for some members holds of the whole class only when the class is projectible for that claim [goodman1955]. Therefore, the record states whether the projection is assumed, tested, or not claimed. *Example*: delayed generalization is reported across several architectures, so a record of trained networks assumes that a mechanism found in one architecture projects onto the class. A theorem quantifying over every member, by contrast, claims no projection. ^projectibility

- **Selection criteria are needed only when membership depends on an outcome of the dynamics**, for a formal class as for an empirical one. A restriction on prior properties, such as the species and brain area of recorded animals, belongs to the domain of the question that imposes it, as eligibility criteria define the population of a clinical trial [ich2019].

- **A criterion on an outcome of the dynamics can create associations that the full class does not show.** *Example*: across the full class, the learning rate and the initialization scale are set independently, but training converges only when their product stays under a threshold. Among the converged networks, a large learning rate then co-occurs with a small initialization scale. This association comes from the selection alone, since convergence is a common effect of both factors [hernan2004]. Each selection criterion is therefore marked as fixed *a priori* or as dependent on an outcome. A claim about members chosen by an outcome transfers to the full class only once it has been checked for this selection bias.

- **State variables fix how the phenomena can be expressed.** The reason is that the explanandum variable of a phenomenon is a *function of the system's state variables* (an "observable"). Likewise, a variable defined over one constituent, or over a pair of them, corresponds to the components and relations of a [mechanism](../answer/mechanism.md).

- **Each entry of a signature resolves to a constituent kind or to an index set, and the two cases are read differently.** An entry resolving to a constituent kind names the bearer of the quantity. In a system with several kinds of unit, such an entry therefore fixes which kind bears the quantity. An entry resolving to an index set, by contrast, names the set along which the quantity varies. A signature entry that resolves to neither is a *defect*.

- **A parameter or a variable names the signature that it takes**, with one entry per place, each a constituent kind or an index set. A quantity of a single unit names one constituent kind, and a quantity of a pair two. A quantity of the whole system names none. The places are generic: a connectivity weight defined over two neurons holds for any pair. A quantity whose single value holds for every tuple is marked as shared. A variable that is an aggregate is declared, in addition to its signature, with its defining map, "[variable] := [function of constituent variables]". ^places

- **The scale of a quantity fixes which comparisons between its values carry meaning.** The scales differ by the structure of their values [stevens1946]:

    - labels support only identity (nominal);
    - an order supports ranking (ordinal);
    - an arbitrary zero supports differences (interval);
    - a natural zero supports ratios (ratio);
    - a count admits no rescaling at all (absolute).

    A claim of dependence is meaningful only when it uses the comparisons that the scale supports. *Example*: "twice as active" is meaningful for a firing rate and meaningless for a regime labelled "synchronous". ^scale

- **Constituent states determine an aggregate, but not a quantity of the whole system.** An aggregate is therefore a *function on the state space*. *Examples*: the center of mass is a mean of positions weighted by mass, the temperature of a gas a mean kinetic energy, a population rate a mean over neurons. The volume of a container, by contrast, is a quantity of the whole system. ^aggregate-variables

- **An aggregate is a legitimate variable only if interventions on it have unambiguous effects.** For example, total cholesterol is ambiguous: raising it through LDL or through HDL has opposite effects on heart disease [spirtes2004]. A mean rate over excitatory and inhibitory neurons is ambiguous for the same reason. The requirement comes from consistency between levels: a model over aggregates must stay consistent with the model over constituents. Consistency holds only if each intervention on an aggregate corresponds to interventions on the constituents [rubenstein2017]. A declared aggregate therefore commits the record to this correspondence. The [individuation test](../answer/satisfaction-conditions.md) holds each candidate answer to that correspondence. ^aggregate-admissibility

- **An aggregation map is carried by its variable, not by a law.** Such a map merely *introduces* its quantity, so it cannot be false of the system. *Example*: the map "population rate := mean of the constituent rates". The expression of a law, in contrast, asserts a claim that can be false. A bridge law falls on the side of the laws: it *identifies a separately measured quantity with an aggregate*, so it is a factual hypothesis. *Example*: the temperature read by a thermometer equals the mean kinetic energy of the molecules, up to a constant. In reduction theory, however, a bridge law has the status either of a stipulation or of an empirical hypothesis [nagel1961]. When a bridge law states an empirical hypothesis, including a bridge law of a reduction, it belongs to the laws of a [background record](background.md), under the role measurement. ^bridge-law

- **Internal variables form the state of the system $S$**: $S$ determines their values, as a causal model fixes its endogenous variables [pearl2009]. The law that determines an internal variable, however, need not be known: such a variable may be only measured, and its law may be admitted, sought by the inquiry, or left open.

- **An external system is fixed by its symbol, the variables that it shares, the constraints that it imposes on them, and its own quantities.** *Examples*: the temperature of a heat bath, the latent dimension of a generator of inputs, the weights of a decoder. Each such quantity is declared among the parameters or the exogenous variables of the record, and names its owner. One symbol table therefore serves the whole record, and a question narrows a quantity of an external system within its [domain](domain.md), as it does a parameter of $S$. A law of an external system, by contrast, is omitted when it involves no shared variable, because such a law cannot act on the target. ^external-parameters

- **A variant that no declaration carries names a member that the record cannot generate.** The other members remain describable, but that variant has no schema at all. The class therefore states a disjunction of variants, and the declarations support only some of its terms. A record may admit the gap by marking the variant open in its [maturity](subject-of-inquiry.md), the field reserved for such gaps. Otherwise, the gap is reported. To detect the gap, the check counts the entries that carry the variant, across every block of declarations in the record and in the background records that describe the target. Occurrences of the variant's name do not count, because that name recurs in its own prose and in the mark that admits the gap. ^unborne-variant

- **A selection criterion conditions membership on an outcome, whereas a restriction on prior values belongs to the question.** A target system serves several phenomena and questions, so a restriction written there binds every inquiry built on the record. Such a binding restriction is correct when the class is a *selected* population, because members selected on an outcome of the dynamics form a class that supports different inferences, and every inquiry must account for that change [lundberg2021]. Such a restriction is incorrect, by contrast, when one inquiry merely asks its question of some members and another would ask it of the rest. That partition of the members is a restriction of the [domain](domain.md), imposed by the question. A restriction that bears on no single quantity is stated as a joint condition. ^selection-on-outcome

- **A variant alters the declarations of a member, whereas a domain restriction changes only the values of its quantities.** When members of one class share every declaration and vary only in their parameter values, a [restriction of the domain](domain.md) captures the difference. Members may instead differ in which quantities and which laws they carry at all. No restriction of values captures such a variation: a consumer model with explicit resource pools and one with direct interaction coefficients have distinct state spaces. The declarations nevertheless stay in one symbol table, because the resolver and every reference between records assume that layout. A variant partitions the symbol table, and its mark labels each entry carried by only some members. An entry left unmarked holds for the whole class, so it may not name a symbol that only some members have. Whether an entry names such a symbol is read from the fields through which its kind refers to symbols. An external system refers to it through the variables that it shares. A law of a [background record](background.md) refers to it through its expression, and a relation of the organization through the parts that it runs between and through its realizing laws. The mark itself must name a declared variant, because an undeclared mark releases its entry from holding for the whole class without assigning it to any member. ^variants




- **A constraint of an external system is a claim, and is recorded with the fields of a law.** The constraint can be false of the system and its environment together. The constraint nevertheless stays with the external system imposing it, not among the laws of a [background record](background.md), for two reasons. First, the block of external systems exists to state the boundary. Second, each admitted law bears on the target alone. ^external-constraint-shape

- **An external system belongs to a class, as the target does.** The target is fixed by a reference class that its specifications generate. For an external system, a name in words and the constraints that it imposes at the boundary leave its kind open, and the class fixes that kind. An answer that appeals to the external system therefore invokes a *kind*. Two inquiries may then appeal to the same kind. The constraints, by contrast, restrict the variables that the external system shares, and therefore also carry any consequence of the class at the boundary. ^external-class

- **External systems enter the specification only through the variables that they share with $S$.** An open system interacts with its environment through variables shared at its boundary [willems2007]. The external systems are therefore specified by the properties that constrain those shared variables. These properties pass the [inclusion test](subject-of-inquiry.md#^inclusion-test) for a specification: they change the admissible answers. For example, an answer may explain the phenomenon by the structure of the inputs, such as the latent variables that generate them [goldt2020]. An answer may also appeal to the class of external system that reads the outputs, such as a linear decoder. A restriction of the parameter ranges of an external system, however, belongs to $D$, as it does for $S$.

- **The boundary is the set of shared variables, declared without a direction.** In the behavioral approach, every interconnection is a set of shared variables, with no prior partition into inputs and outputs [willems2007]. Where a partition into inputs and outputs applies, the declarations still recover that split: a shared exogenous variable is set outside $S$, and a shared state variable is determined inside $S$. A shared state variable that an external system also constrains closes a loop. The boundary therefore needs no explicit direction: the declarations already fix the orientation.

- **The partition of variables is only provisional.** The constituents, the state variables and the shared ones record the partition that the researcher *stipulates*. *Examples*: an isolated slice, or a closed loop with a task environment. Some inquiries, however, partly *establish* the relevant partition themselves. *Example*: in [constitutive explanation](../epistemic-task/requested-relation.md), a part belongs to the mechanism only if its activity and the system's behavior can each be changed by intervening on the other ("mutual manipulability") [craver2007]. The inquiry may then move a variable across the boundary, for instance by enlarging $S$ to include the task environment.
