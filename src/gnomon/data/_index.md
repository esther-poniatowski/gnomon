# Framework data

The data the package ships: the shapes a project fills, the vocabularies and requirements the checkers read, and the material the wider workflow draws on. A method note documents each vocabulary and is checked against it, so no check depends on a document.

- [The record shapes a project copies and fills](templates/_index.md) carry one file per inquiry layer, in the order of the method note that defines each.
- [The operators the framework supplies](operators.yml) fix what a formula may use before a problem declares mathematics of its own. Documented by [the syntax of symbols and expressions](../../../docs/epistemology/symbols-and-expressions.md).
- [The values each closed field admits](vocabularies.yml) fix what a filled record may hold, per field. Documented by the option list beside each field of [the record shapes](templates/_index.md).
- [What a filled inquiry must carry](requirements.yml) lists the specifications every record holds, what each level of commitment requires of a target system or a phenomenon, and what each epistemic aim adds or produces. Documented by [the aims an inquiry can pursue](../../../docs/epistemology/epistemic-aim.md) and by the requirement column of each method note.
- [The obligations a note accepts before and after drafting](contracts/_index.md) hold one contract per note type, separating what binds the draft from what is checked afterwards.
- [The epistemic activities and the product types](registries/_index.md) fix what each step of an itinerary may take and produce. Documented by [the taxonomy of epistemic activities](../../../docs/epistemology/definitions/activities/epistemic-activities.md).
- [The schemas validating that state](schemas/_index.md) accompany the registry shapes.
- [What each note type requires and forbids](specs/_index.md) fixes the sections of a note, with the template a new one starts from.
- [The staged pipeline and its control points](workflow/_index.md) separates the reasoning passes and where a person intervenes.
